## 📌 导读：为什么基本数据类型容易出错？

计算机内存只是按**字节**编址的一串二进制，**类型**只做两件事：

1. **决定占几个字节**（宽度）；
2. **决定这段 0/1 如何被解释**（有符号？浮点？）。

而编译器在**不报错**的前提下，会悄悄替你做大量转换——**整型提升、算术转换、隐式截断、精度舍入**。于是"看起来天经地义"的代码，跑出来却是另一个数。

> 💡 **三大万恶之源**
>
> - **宽度不同**：`char / short → int → long → long long`
> - **有无符号**：`signed` 与 `unsigned` 混算，负数瞬间"变"成天文数字
> - **求值顺序**：表达式里既有读又有写（副作用），结果由编译器"自由发挥"

**结论先行**：期中题里 90% 的"诡异结果"，都可以归结为 **"隐式转换" + "未定义行为"** 这两件事。下面逐模块拆解。

## 模块一：整型与浮点型的暗坑

### 💡 1.1 隐式类型转换（整型提升 & 算术转换）

**整型提升（Integer Promotion）**：`char`、`short`（及 `bool`）在参与运算前，会先被提升为 `int`（若 `int` 装得下）。

**寻常算术转换（Usual Arithmetic Conversions）**：两边类型不同时，向"更宽/更精"的一方看齐：

```c
// 精度由低到高的"鄙视链"（简化版）
int → unsigned int → long → unsigned long → long long
    → float → double → long double
// 规则：低的一方被提升到高的一方，再运算
```

#### ⚠️ 陷阱 A：char 相加"看起来溢出"，其实没有

```c
// ❌ 错误直觉：两个 char 相加会溢出成负数
char a = 100, b = 100;
printf("%d\n", a + b);   // 输出 200 ！

// 原因：a、b 先被"整型提升"为 int，100+100=200 完全装得下
```

```c
// ✅ 正确认知：真正溢出发生在"赋值回窄类型"的那一刻
char a = 100, b = 100;
char c = a + b;          // a+b 是 int 的 200，赋给 char 时被截断
printf("%d\n", c);       // 输出 -56（有符号 char，8 位只留低 8 位）
```

#### ⚠️ 陷阱 B：宽类型转窄类型，高位直接"砍掉"

```c
// ❌ 错误直觉：int 转 short 只是"换个名字"
int  x = 70000;
short s = x;             // 70000 = 0x11170，short 只留低 16 位 0x1170
printf("%d\n", s);       // 输出 4464（甚至可能为负，取决于符号位）
```

```c
// ✅ 正确做法：跨宽度转换前先想清楚范围，必要时显式强转并检查
long long big = 70000;
short s = (short)big;    // 强转是"截断"，不是"四舍五入"
// 需要保证数值不变时，应确保目标类型范围足够大（如用 int / long）
```

#### ⚠️ 陷阱 C：浮点转整型不是"四舍五入"，是"向零截断"

```c
// ❌ 错误直觉：会四舍五入
int a = (int)3.99;       // 3，不是 4
int b = (int)-3.99;      // -3，不是 -4（向 0 方向截断）
```

```c
// ✅ 正确做法：需要四舍五入时用库函数
#include <math.h>
int a = (int)round(3.99);   // 4
int b = (int)floor(-3.99);  // 需要向下取整时用 floor
```

#### ⚠️ 陷阱 D：int 转 float 也丢精度（很多人不知道）

```c
// ❌ 错误直觉：float 比 int "高级"，转换一定无损
int   n = 16777217;        // 2^24 + 1
float f = n;               // float 尾数只有 24 位有效位
printf("%d\n", (int)f);    // 输出 16777216 ！末位被舍掉了
```

```c
// ✅ 正确认知：float 只能精确表示 |x| <= 2^24 的整数
// 需要保存大整数精度时，用 double（可到 2^53）或直接保留整型
int    n = 16777217;
double d = n;              // 2^24+1 在 double 中可精确表示
printf("%.0f\n", d);       // 16777217
```

> 🛡️ **避坑口诀**：**"提升无害，截断要命；跨类型前，先看范围。"**

### 💡 1.2 浮点数精度问题

| 类型 | 典型字节 | 有效十进制位 | 尾数位数 | 典型机器精度 |
| :--- | :---: | :---: | :---: | :--- |
| `float` | 4 | **约 6~7 位** | 24 bit | `FLT_EPSILON ≈ 1.19e-7` |
| `double` | 8 | **约 15~16 位** | 53 bit | `DBL_EPSILON ≈ 2.22e-16` |

#### ⚠️ 陷阱 E：`0.1 + 0.2 != 0.3`（浮点不能直接 `==`）

```c
// ❌ 错误写法：直接判等
if (0.1 + 0.2 == 0.3)
    printf("相等\n");     // 永远不会打印！
// 原因：0.1、0.2、0.3 在二进制里都是无限循环小数，存储时已被舍入
//       0.1+0.2 的实际结果 ≈ 0.30000000000000004，与 0.3 差一个 ulp
```

```c
// ✅ 正确写法：用"误差容限 EPS"判断
#include <math.h>
#define EPS 1e-9
if (fabs((0.1 + 0.2) - 0.3) < EPS)
    printf("在误差范围内相等\n");
// 工程上更严谨：fabs(a-b) <= EPS * fmax(1.0, fmax(fabs(a), fabs(b)))
```

#### ⚠️ 陷阱 F：`float` 与 `double` 混用，比较"翻车"

```c
// ❌ 错误直觉：0.1f 和 0.1 都是 0.1
float f = 0.1f;
if (f == 0.1)            // 0.1f 提升为 double 后 ≠ double 的 0.1
    printf("相等\n");     // 不会打印
```

```c
// ✅ 正确做法：统一精度，或统一用 EPS 比较
float  f = 0.1f;
double d = 0.1;
if (fabs((double)f - d) < 1e-9) printf("近似相等\n");
```

#### ⚠️ 陷阱 G：`printf / scanf` 格式符与类型不匹配

```c
// ❌ 错误写法
float  f = 3.14f;
printf("%lf\n", f);      // printf 中 %lf 与 %f 等价，尚可；
double d = 3.14;
scanf("%f", &d);         // 致命！%f 要求 float*，传 double* 是未定义行为

// ❌ 用 %d 打印 size_t / 浮点，同样是未定义行为
printf("%d\n", sizeof(int));   // 64 位下应使用 %zu
```

```c
// ✅ 正确写法：printf 中 float 会自动提升为 double，用 %f 即可
printf("%f\n", 3.14f);        // OK，float 实参被提升为 double
scanf("%lf", &d);             // double 用 %lf
printf("%zu\n", sizeof(int)); // size_t 用 %zu
```

> 📊 **一句话总结**：**浮点数天生"近似"，判等必须给容差；`float` 存小数用 `1.0f`，别和 `double` 较真。**

## 模块二：符号位带来的灾难（unsigned 与 signed 的较量）

### 💡 2.1 核心规则：有符号遇到无符号，有符号"被迫从良"

当 `int` 与 `unsigned int` 混合运算时，**`int` 会被转换成 `unsigned int`**（因为 `unsigned int` 表示范围更大，`int` 无法"装下"它）。

**结果：负数 `-1` 变成 `4294967295`（2³²−1）。**

#### ⚠️ 陷阱 H：`-1 < 1u` 竟然是 **假**

```c
// ❌ 错误直觉：-1 当然小于 1
if (-1 < 1u)
    printf("真\n");        // 不打印！
// 实际：-1 被转成 0xFFFFFFFF = 4294967295，4294967295 < 1 为假
```

```c
// ✅ 正确做法：避免有符号与无符号混比；必要时显式转成同一类型
if (-1 < (int)1u)          // 转成 int 后比较：-1 < 1 为真
    printf("真\n");
// 更稳：根本不要让有符号变量去和无符号量比较
```

#### ⚠️ 陷阱 I：`strlen(...) - 1 >= 0` 永远为真（考试高频！）

```c
// ❌ 错误写法：想判断字符串非空
char s[] = "";
if (strlen(s) - 1 >= 0)     // strlen 返回 size_t（无符号）
    printf("非空\n");        // 空串也会打印！因为 0-1 在无符号里是巨大正数
```

```c
// ✅ 正确写法
if (strlen(s) > 0)          // 直接和无符号比较，安全
    printf("非空\n");
// 或先转有符号：if ((int)strlen(s) - 1 >= 0) ...
```

#### ⚠️ 陷阱 J：`for (unsigned i = n; i >= 0; i--)` 死循环

```c
// ❌ 错误写法：无符号变量永远 >= 0
for (unsigned i = 10; i >= 0; i--)
    printf("%u ", i);       // 打印到 0 后 i-- 变成 4294967295，无限循环
```

```c
// ✅ 正确写法一（推荐）：用有符号循环变量
for (int i = 10; i >= 0; i--) printf("%d ", i);

// ✅ 正确写法二：确实要用无符号时，用 do-while 保证能打印到 0
unsigned i = 10;
do { printf("%u ", i); } while (i-- > 0);
```

#### ⚠️ 陷阱 K：`sizeof` 返回值也是无符号，参与减法同样危险

```c
// ❌ 错误写法
if (sizeof(int) - 5 > 0)     // 4 - 5 在 size_t 里是巨大正数 > 0，为真
    printf("陷阱\n");
```

```c
// ✅ 正确写法：先转 int 再算，或改用无符号安全的判断
if ((int)sizeof(int) - 5 > 0) { /* 此时为假，逻辑正确 */ }
```

> 🛡️ **避坑铁律**：**"有符号 + 无符号 = 无符号；负数一进无符号，立刻变巨无霸。"** 看到 `size_t`、`strlen`、`sizeof`、`unsigned`，先警惕减法与比较。

## 模块三：表达式求值与自增自减（副作用与顺序点）

### 💡 3.1 什么是"顺序点"？

**顺序点（Sequence Point）** 是程序执行中的一个"检查站"：在它之前的所有**副作用**（对变量的写操作）都必须完成，之后的操作才能开始。

**关键顺序点**：`;`（分号）、`&&`、`||`、`?:`、逗号运算符、函数调用前的实参求值完成处。

> ⚠️ **核心规则**：**在两个顺序点之间，同一个变量最多被"修改"一次**。若既读又写、或写两次，就是 **未定义行为（UB）**。

> 💡 **C11 小贴士**：新标准把这套规则表述为"sequenced before / unsequenced"，但**判定方法不变**——同一变量在无顺序点间隔处被多次修改，就是 UB。考研选择题仍按"顺序点"理解即可。

#### ⚠️ 陷阱 L：`i++ + ++i` —— 经典未定义行为

```c
// ❌ 错误直觉：以为有固定结果
int i = 5;
int r = i++ + ++i;      // UB！不同编译器/优化级别结果不同
// 可能是 5+7=12，也可能是 6+7=13，甚至行为不可预测
printf("%d %d\n", r, i);
```

```c
// ✅ 正确写法：拆成独立语句，明确先后
int i = 5;
int a = i++;            // a = 5，i 变 6
int b = ++i;            // i 先变 7，b = 7
int r = a + b;          // r = 12，结果确定
printf("%d %d\n", r, i); // 12 7
```

#### ⚠️ 陷阱 M：`printf("%d %d", i++, ++i)` 参数求值顺序未定义

```c
// ❌ 错误写法：函数实参求值顺序标准未规定
int i = 1;
printf("%d %d\n", i++, ++i);   // UB，且读写同一变量无顺序点
```

```c
// ✅ 正确写法：先算好再打印
int i = 1;
int x = i++;
int y = ++i;
printf("%d %d\n", x, y);       // 1 3（x=1, i=2, y=3）
```

#### ⚠️ 陷阱 N：`a[i] = i++` 也是 UB

```c
// ❌ 错误写法：左边用 i 做下标，右边又修改 i
int i = 0, a[10] = {0};
a[i] = i++;             // UB：i 在同一表达式中既被读又被写
```

```c
// ✅ 正确写法：下标与自增分开
int i = 0, a[10] = {0};
a[i] = i;               // 先把值放对位置
i++;                    // 再自增
```

#### ⚠️ 陷阱 O：`i = i++ + 1` / `i = ++i` 同样是 UB

```c
// ❌ 错误写法
int i = 0;
i = i++ + 1;            // UB：i 被改两次且中间无顺序点
i = ++i;                // UB
```

```c
// ✅ 正确写法
int i = 0;
i = i + 1;              // 想要"加一"，直接写清楚
```

> 🛡️ **避坑铁律**：**"一个顺序点内，同一变量只改一次；看见 `i++` 与 `++i` 同框，先判 UB。"**

## 模块四：运算符的执行顺序与短路求值 ⭐ 新增

### 💡 4.1 三个概念别混淆：优先级、结合性、求值顺序

| 概念 | 回答的问题 | 例子 |
| :--- | :--- | :--- |
| **优先级** | 谁先"抱团"成子表达式 | `1 + 2 * 3` → `1 + (2*3)` |
| **结合性** | 同级运算符从左还是从右抱团 | `a = b = c` → `a = (b = c)`（右结合） |
| **求值顺序** | 各操作数**谁先执行** | `f() + g()` 中 f、g 谁先调用？**未指定** |

> ⚠️ **最重要的认知**：**优先级和结合性只决定"怎么分组（语法结构）"，并不决定"谁先算（执行顺序）"！** 这是期中判断题的高频雷区。

#### ⚠️ 陷阱 P：以为"优先级高就先执行"

```c
// ❌ 错误直觉：* 优先级高，所以 g() 一定先于 f() 执行
int r = f() + g() * h();
// 结构确实是 f() + (g()*h())，
// 但 f、g、h 三个函数"实际调用顺序"标准未指定！
```

```c
// ✅ 正确认知：C 只保证"先算出 (g()*h()) 再与 f() 相加"这个层级，
//    不保证 g()、h()、f() 的调用先后；若它们有副作用（改同一全局变量），结果不可移植
```

> 💡 **只有 4 类运算符规定了求值顺序**：`&&`、`||`、`?:`、`,`（逗号）。其余二元运算符、函数实参，求值顺序都是 **unspecified（未指定）**。

---

### 💡 4.2 短路求值（Short-circuit Evaluation）

**规则**：

- `A && B`：先算 `A`，**若 A 为假（0），直接得 0，`B` 根本不执行**；
- `A || B`：先算 `A`，**若 A 为真（非 0），直接得 1，`B` 根本不执行**；
- 逻辑运算的结果类型是 **`int`**，只有 `0` 或 `1`。

#### ⚠️ 陷阱 Q：判空与解引用顺序写反 → 空指针崩溃

```c
// ❌ 错误写法：先解引用，再判空
int *p = NULL;
if (*p > 0 && p != NULL) { }   // 崩溃：&& 左边先执行，*p 直接访问空指针
```

```c
// ✅ 正确写法：先判空，再解引用（利用短路"护住"右边）
int *p = NULL;
if (p != NULL && *p > 0) { }   // p 为 NULL 时右边被短路，安全
```

#### ⚠️ 陷阱 R：短路让副作用"凭空消失"

```c
// ❌ 错误直觉：以为 i++ 和 j++ 都会执行
int i = 0, j = 0;
if (i++ > 0 && j++ > 0) { }    // 左边 0>0 为假 → 短路，j++ 根本不执行
printf("%d %d\n", i, j);       // 输出 1 0（j 没变！）
```

```c
// ✅ 正确认知：需要两边都自增，就不要依赖逻辑表达式
int i = 0, j = 0;
i++;
j++;
if (i > 0 && j > 0) { }
printf("%d %d\n", i, j);       // 1 1
```

> ⚠️ 同理 `i > 0 || j++ > 0`：只要 `i > 0` 为真，`j++` 也不会执行。

#### ⚠️ 陷阱 S：用短路做"边界保护"（正确姿势）

```c
// ✅ 推荐：i 越界时，a[i] 不会被访问
int a[10];
int i = 20;
if (i >= 0 && i < 10 && a[i] > 0) { }   // 第三个条件被短路，不越界
```

#### ⚠️ 陷阱 T：`&` 不短路，`&&` 才短路

```c
// ❌ 错误写法：误用位与（不短路），除零照样发生
int x = 0;
if (x != 0 & 1 / x > 0) { }    // & 两边都算，1/x 除零 → 崩溃
```

```c
// ✅ 正确写法：逻辑与才短路
int x = 0;
if (x != 0 && 1 / x > 0) { }   // 左边假，1/x 不执行，安全
```

> 📊 **`&&` / `&`、`||` / `|` 对比**

| 写法 | 类型 | 是否短路 | 典型用途 |
| :--- | :--- | :--- | :--- |
| `&&` | 逻辑与 | **是** | 条件组合、判空保护 |
| `&` | 按位与 | 否 | 位掩码、清位 |
| \|\| | 逻辑或 | **是** | 条件组合 |
| \| | 按位或 | 否 | 置位、标志合并 |

### 💡 4.3 条件运算符 `?:`

- **结合性**：**右结合**。`a ? b : c ? d : e` 等价于 `a ? b : (c ? d : e)`。
- **求值顺序**：先算条件 `a`，然后**两个分支只算其中一个**（天然短路）。
- **类型陷阱**：两个分支类型不同时，会按"寻常算术转换"统一类型，整个表达式的结果类型可能被"悄悄提升"。

#### ⚠️ 陷阱 U：两分支类型不同，结果被提升

```c
// ❌ 错误直觉：1 ? 1 : 2.0 的结果是 int
// 实际：2.0 是 double，两个分支被统一为 double，整个表达式类型是 double
printf("%d\n", 1 ? 1 : 2.0);   // UB！用 %d 打印 double 是未定义行为
```

```c
// ✅ 正确写法：类型一致，或显式强转
printf("%d\n", 1 ? 1 : 2);          // 两分支都是 int
printf("%f\n", 1 ? 1.0 : 2.0);      // 两分支都是 double
printf("%d\n", 1 ? 1 : (int)2.0);   // 强转统一为 int
```

#### ⚠️ 陷阱 V：嵌套 `?:` 的结合顺序

```c
// 表达式：a ? 1 : b ? 2 : 3   →  右结合
// 等价于：a ? 1 : (b ? 2 : 3)
// 千万别说成 (a?1:b) ? 2 : 3
```

---

### 💡 4.4 逗号运算符

- **求值顺序**：从左到右，**是一个顺序点**；
- **整体表达式的值**：最后一个子表达式的值；
- ⚠️ 与**函数实参分隔符**的逗号、**声明语句**里的逗号，完全不是一回事。

#### ⚠️ 陷阱 W：把函数实参的逗号当成逗号运算符

```c
// ❌ 误解：以为 f 只收到一个参数
f(a, b);        // 这是"两个实参"，逗号是分隔符，不是逗号运算符
```

```c
// ✅ 逗号运算符要用括号包成一个整体
int x = (a = 1, b = 2, a + b);   // 依次执行，x = 3，a=1，b=2
```

#### ⚠️ 陷阱 X：声明里的逗号不是逗号运算符

```c
int a = 1, b = 2;      // 声明两个变量，逗号是分隔符
int c = (1, 2);        // 逗号运算符，c = 2（整体取最后一个值）
```

---

### 💡 4.5 赋值运算符与"连等"陷阱

- **赋值**：**右结合**，`a = b = c` 等价 `a = (b = c)`；
- **赋值表达式的值**：就是"被赋进去的那个值"，所以可以连用；
- ⚠️ 但 `==` 是**左结合**，`a == b == c` 是 `(a == b) == c`，先得 0/1 再和 c 比！

#### ⚠️ 陷阱 Y：`a == b == c` 不判断"三者相等"

```c
// ❌ 错误写法：以为在判断 a、b、c 三者相等
if (a == b == c)       // 实际是 (a==b) 得 0/1，再与 c 比较
    printf("相等\n");
```

```c
// ✅ 正确写法
if (a == b && b == c)
    printf("三者相等\n");
```

#### ⚠️ 陷阱 Z：复合赋值与自增混用

```c
// ❌ 写法含义不清（且 i 被多次修改）
int i = 0, a[10] = {0};
a[i++] += 5;           // i 在左值里被改，虽有明确定义但极易读错
```

```c
// ✅ 拆开写，意图清晰
int i = 0, a[10] = {0};
a[i] += 5;
i++;
```

---

### 💡 4.6 自增自减的"左值"问题

- `i++` 的值是**旧值**，`++i` 的值是**新值**；
- `i++` **不是左值**，所以 `(i++)++` 非法；`++i` 在 C 中也**不是左值**（C++ 中是），故 `++i = 5` 在 C 里非法。

```c
// ❌ 非法写法
int i = 0;
(i++)++;        // 错误：i++ 不是可修改的左值
++i = 5;        // 错误：C 中 ++i 不是左值
```

```c
// ✅ 正确写法
int i = 0;
i++;
i = 5;
```

---

### 💡 4.7 函数调用与实参求值顺序

- 函数**实参的求值顺序未指定**（unspecified）；
- `printf("%d %d", f(), g())` 中，先打印 f 还是先打印 g **无保证**；
- 若两个实参都修改同一变量 → **UB**。

```c
// ❌ UB：两个实参都改 i
int i = 0;
printf("%d %d\n", i++, i++);
```

```c
// ✅ 正确写法
int i = 0;
int a = i++;
int b = i++;
printf("%d %d\n", a, b);   // 0 1
```

### 📊 4.8 运算符优先级速记表（从高到低）

| 级别 | 运算符 | 结合性 |
| :---: | :--- | :--- |
| 1 | `()` `[]` `->` `.` 后缀 `++` `--` | 左→右 |
| 2 | 单目 `!` `~` `++` `--` `+` `-` `*` `&` `(类型)` `sizeof` | 右→左 |
| 3 | `*` `/` `%` | 左→右 |
| 4 | `+` `-` | 左→右 |
| 5 | `<<` `>>` | 左→右 |
| 6 | `<` `<=` `>` `>=` | 左→右 |
| 7 | `==` `!=` | 左→右 |
| 8 | `&`（按位与） | 左→右 |
| 9 | `^`（按位异或） | 左→右 |
| 10 | \|（按位或） | 左→右 |
| 11 | `&&` | 左→右 |
| 12 | \|\| | 左→右 |
| 13 | `?:` | 右→左 |
| 14 | `=` `+=` `-=` `*=` `/=` `%=` 等赋值 | 右→左 |
| 15 | `,`（逗号） | 左→右 |

> ⚠️ **高频易错点**：`==` 优先级**高于** `&`、`^`、`|`；`+` 高于 `<<`；所以 `a & b == 0`、`1 << 2 + 3` 都极易写错——**不确定就加括号**。

#### ⚠️ 优先级典型对照

| 表达式 | 易错理解 | 实际含义 | 结果 |
| :--- | :--- | :--- | :--- |
| `*p++` | `(*p)++` | `*(p++)` | 先取指针再加，再解引用 |
| `-x++` | `(-x)++` | `-(x++)` | `++` 先与 x 结合 |
| `!x == y` | `!(x == y)` | `(!x) == y` | `!` 优先级高于 `==` |
| `a & b == 0` | `(a & b) == 0` | `a & (b == 0)` | 应加括号 |
| `1 << 2 + 3` | `(1 << 2) + 3` | `1 << (2 + 3)` | `32`，不是 `7` |

## 模块五：看似简单的常量与 `sizeof`

### 💡 5.1 字面量后缀的区别

| 字面量 | 类型 | 说明 |
| :--- | :--- | :--- |
| `123` | `int` | 默认整型 |
| `123L` / `123l` | `long` | 长整型（Windows 下仍 4 字节，Linux 64 位 8 字节） |
| `123LL` | `long long` | 至少 8 字节 |
| `123U` | `unsigned int` | 无符号 |
| `123UL` | `unsigned long` | 无符号长整型 |
| `1.0` | **`double`** | 默认浮点就是 double！ |
| `1.0f` | **`float`** | 单精度 |
| `1.0L` | `long double` | 长双精度 |

#### ⚠️ 陷阱 AA：`1.0` 是 double，不是 float

```c
// ❌ 错误直觉：1.0 是 float
float f = 1.0;          // 1.0 是 double，赋值时发生"double → float"隐式转换
// 若在重载/模板/printf 中依赖类型，就可能出错
```

```c
// ✅ 正确写法：明确要 float 就加 f
float f = 1.0f;         // 无多余的精度转换，语义清晰
```

#### ⚠️ 陷阱 AB：整数除法丢小数

```c
// ❌ 错误写法
double avg = 5 / 2;     // 5/2 是整数除法 = 2，再转 double 得 2.000000
printf("%f\n", avg);    // 2.000000
```

```c
// ✅ 正确写法：至少一边是浮点
double avg = 5 / 2.0;   // = 2.5
// 或 double avg = (double)5 / 2;
```

### 💡 5.2 进制书写陷阱

```c
// ❌ 非法常量（编译直接报错）
int a = 09;      // 错误：八进制不允许数字 9
int b = 08;      // 错误：八进制不允许数字 8
int c = 0x1G;    // 错误：十六进制不允许 G
```

```c
// ✅ 正确写法
int a = 010;     // 八进制，等于十进制 8
int b = 017;     // 八进制，等于十进制 15
int c = 0x1F;    // 十六进制，等于十进制 31
int d = 0b1010;  // C99/GCC 扩展：二进制，等于 10（标准 C 不保证支持）
```

> ⚠️ **记忆点**：**"八进制以 0 开头、只含 0~7；十六进制以 0x 开头、含 0~9 / a~f。"** 看到 0 开头的数字，先数有没有 8、9。

### 💡 5.3 `sizeof` 陷阱（重点大户）

**`sizeof` 是运算符，不是函数**；它在**编译期**求值，**不会真正执行**括号里的表达式（可变长数组除外）。

#### ⚠️ 陷阱 AC：`sizeof(数组)` 与 `sizeof(指针)` 天差地别

```c
// ❌ 错误直觉：在函数里也能算数组长度
void f(int arr[10]) {
    printf("%zu\n", sizeof(arr));          // 输出 8（指针大小），不是 40！
}
int a[10];
f(a);   // 数组名传参后退化为指针
```

```c
// ✅ 正确做法：数组长度必须在"数组未退化"的作用域内计算
int a[10];
size_t n = sizeof(a) / sizeof(a[0]);       // 40/4 = 10，正确
// 跨函数时，必须把长度作为参数一起传进去
void f(int arr[], int n) { /* 用 n，不要用 sizeof(arr) */ }
```

#### ⚠️ 陷阱 AD：`sizeof` 里的表达式不会被执行

```c
// ❌ 错误直觉：以为 i++ 会执行
int i = 5;
size_t s = sizeof(i++);    // i++ 不被求值（无副作用）
printf("%d\n", i);         // 输出 5，i 没变
```

```c
// ✅ 正确认知：sizeof 只求"类型大小"，副作用不发生
// 若确实需要自增，请另起一条语句：i++;
```

#### ⚠️ 陷阱 AE：`sizeof('a')` 在 C 里是 4，不是 1

```c
// ❌ 错误直觉：字符就是 1 字节
printf("%zu\n", sizeof('a'));   // C 中字符常量的类型是 int，结果 = 4
printf("%zu\n", sizeof(char));  // 结果 = 1
```

```c
// ✅ 正确认知：'a' 是 int 常量（值 97），char 变量才是 1 字节
char ch = 'a';
printf("%zu\n", sizeof(ch));    // 1
```

#### ⚠️ 陷阱 AF：`sizeof` 结果类型是无符号，负数比较翻车

```c
// ❌ 错误写法（同陷阱 K）
if (sizeof(int) - 5 > 0) printf("真\n");   // 永远为真

// ✅ 正确写法
if ((int)sizeof(int) - 5 > 0) printf("真\n");
```

> 📊 **`sizeof` 速查表**

| 表达式 | 典型结果（32/64 位常见平台） | 关键点 |
| :--- | :--- | :--- |
| `sizeof(char)` | 1 | 标准规定恒为 1 |
| `sizeof(int)` | 4 | 最常见 |
| `sizeof('a')` | **4（C）/ 1（C++）** | 字符常量是 int |
| `sizeof(1.0)` | 8 | double |
| `sizeof(1.0f)` | 4 | float |
| `sizeof(1L)` | 4（Windows）/ 8（Linux 64） | 平台相关 |
| `sizeof(int *)` | 4 / 8 | 指针大小随平台 |
| `sizeof(a) / sizeof(a[0])` | 数组元素个数 | 仅在数组未退化时有效 |

## 📊 终极对比总结表

| # | 陷阱场景 | ❌ 错误写法 / 错误直觉 | ✅ 正确写法 / 标准结论 |
| :---: | :--- | :--- | :--- |
| 1 | 有符号负数比无符号 | `-1 < 1u` 为真 | 为**假**，`-1` 变 `4294967295`；应转同类型再比 |
| 2 | `strlen` 减法判空 | `strlen(s)-1 >= 0` 判非空 | 恒真；应写 `strlen(s) > 0` |
| 3 | 无符号倒序循环 | `for(unsigned i=n;i>=0;i--)` | 死循环；用 `int` 或 `do-while` |
| 4 | 浮点判等 | `0.1+0.2 == 0.3` | 恒假；用 `fabs(a-b) < EPS` |
| 5 | float 与 double 混比 | `0.1f == 0.1` | 恒假；统一精度或 EPS 比较 |
| 6 | 整数除法 | `5/2` 求平均 | 得 2；应写 `5/2.0` 或强转 |
| 7 | 浮点转整型 | `(int)3.99` 得 4 | 得 3，**向零截断**；四舍五入用 `round` |
| 8 | int 转 float | 以为无损 | **超 2²⁴ 丢精度**；大整数用 `double` 或留整型 |
| 9 | `i++ + ++i` | 以为有固定值 | **未定义行为**；拆成多条语句 |
| 10 | `a[i] = i++` | 以为先算后赋 | UB；下标与自增分开写 |
| 11 | `i = i++ + 1` | 以为就是加一 | UB；应写 `i = i + 1` |
| 12 | 位移优先级 | `1 << 2 + 3` 当 `(1<<2)+3` | 实际 `1 << 5 = 32`；加括号 |
| 13 | 位与优先级 | `a & b == 0` 当 `(a&b)==0` | 实际 `a & (b==0)`；加括号 |
| 14 | 短路副作用 | `i++>0 && j++>0` 以为都执行 | 左假则 `j++` **不执行**；副作用会消失 |
| 15 | 判空顺序 | `*p>0 && p!=NULL` | **空指针崩溃**；应 `p!=NULL && *p>0` |
| 16 | `&` 当逻辑与 | `x!=0 & 1/x>0` | **不短路**，除零崩溃；应用 `&&` |
| 17 | `==` 连等 | `a == b == c` | 实为 `(a==b)==c`；应 `a==b && b==c` |
| 18 | `?:` 分支类型 | `cond ? 1 : 2.0` 当 int | 整体是 **double**；用 `%d` 打印是 UB |
| 19 | 求值顺序误解 | 以为优先级高就先执行 | 优先级≠求值顺序；二元运算符顺序**未指定** |
| 20 | 函数实参顺序 | `printf("%d %d", i++, i++)` | **UB**；先算好再打印 |
| 21 | 八进制常量 | `int a = 09;` | **非法**；八进制只能 0~7 |
| 22 | 浮点字面量类型 | `float f = 1.0;` | `1.0` 是 double；要 float 写 `1.0f` |
| 23 | `sizeof('a')` | 以为等于 1 | C 中等于 **4**（`'a'` 是 int） |
| 24 | `sizeof` 算数组长度 | 函数内 `sizeof(arr)/sizeof(arr[0])` | 退化为指针，得到错误值；须传长度参数 |
| 25 | `sizeof(i++)` | 以为 i 会自增 | 表达式**不执行**，i 不变 |
| 26 | printf 格式符 | `scanf("%f",&d)`（d 是 double） | 应 `%lf`；否则未定义行为 |
| 27 | size_t 打印 | `printf("%d", sizeof(x))` | 应用 `%zu` |

## 💡 考场实战口诀

> **一、类型转换篇**
>
> 提升无害截断险，窄赋宽转要看清；
>
> 浮点转整向零截，四舍五入靠 `round`。

> **二、符号位篇**
>
> 有符无符一相见，有符立刻变无符；
>
> 负数一进无符号，四十二亿等着你。

> **三、浮点篇**
>
> 浮点天生是近似，判等千万莫用 `==`；
>
> 容差 EPS 来兜底，`1.0` 是双 `1.0f` 单。

> **四、自增与顺序点篇**
>
> 一个顺序点之内，同个变量只改一次；
>
> `i++ + ++i` 是雷区，看见就判未定义。

> **五、短路与求值篇**
>
> `&&` `||` 才短路，`&` `|` 两边都得算；
>
> 先判空、后解引用，判空顺序不能反；
>
> 优先级只管分组，谁先执行它不管。

> **六、常量与 `sizeof` 篇**
>
> 零头八进制无八九，`0x` 十六放心写；
>
> 后缀 `L` 长 `f` 单精，字面量类型要记清；
>
> `sizeof` 是运算符，数组退化要当心，
>
> 括号表达式不执行，`sizeof('a')` 却是四。

> 🎯 **终极一句话**：**"转换看范围，比较看符号，判等给容差，求值看顺序，短路看左右，`sizeof` 看类型。"**
